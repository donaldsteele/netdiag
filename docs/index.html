Know what is on your network in ten seconds.

Printers, web pages, IP conflicts, and the health of the gateway, DHCP, DNS and Wi-Fi, in one window.

netdiag sweeps the local subnet with ping, ARP, port probes, SNMP, mDNS and IPP, then shows what answered, what it is, and what is wrong with it. Built for whoever gets the call when the printer stops or the Wi-Fi “is down”.

What it finds

Everything that answered, and what is wrong with it.

Every status has a shape and a word, never colour alone. Nothing is changed on any device: every probe is read-only.

Every device

Parallel ping sweep plus the ARP table, so devices that block ping still show up. Vendor from the MAC, names from DNS and mDNS.

Printers, in detail

Model, serial, page count, toner and drum levels, trays, covers and alerts over SNMP and IPP. Jams and open doors in seconds in live mode.

Web pages

Ports 80, 443, 8080 and 8443 probed for status, title, server and certificate, with a link to open each one.

Network health

Gateway, DHCP lease, DNS, a web server you rely on, internet reachability and Wi-Fi signal, each with a plain-word status.

IP conflicts

Two devices fighting over one address, one MAC on many IPs, or duplicate names. Mesh nodes and extenders can be ignored in one click.

Live alerts

Leave it running: banners, a beep and optional desktop notifications when a printer jams, a supply runs low or a device drops off.

Device types

Printer, TV, NAS, phone, camera, network gear, smart home and more, from real signals. Unknown stays unknown: no guessing.

History & compare

Every scan is saved. Compare any two to see what was added, removed or changed, and export it as JSON or CSV.

Health

Is it the network, or the device?

One card per check with a status word, the detail and the response time. A health problem never stops a scan, and the internet check is information only, because plenty of local networks have no internet at all.

New in 0.5

Ask Claude what is wrong with the network.

netdiag speaks MCP (Model Context Protocol), so Claude or another AI agent on this computer can read scan results and run diagnostics, and explain them in plain words.

Terminal · Claude Code
$ claude mcp add netdiag -- "C:\path\to\netdiag.exe" mcp
$ claude mcp list
netdiag: … mcp - ✔ Connected
> Use netdiag to scan the network and tell me why the Brother printer is offline.

On a Mac use /path/to/netdiag mcp. Claude Desktop and sharing the open window over HTTP are covered in the README.

Built-in playbooks

  • triage_network What needs attention first?
  • diagnose_printer Why is this printer not printing?
  • explain_conflict Who is fighting over this IP?
  • device_missing Why is this laptop not showing up?
  • what_changed What is different since the last scan?
  • Read and diagnose only: agents cannot change settings, delete history or quit.
  • The SNMP community string is never shown to the agent.
  • This computer only (127.0.0.1). HTTP access is off until you switch it on.

macOS

Apple silicon (M1 and later) Intel

  1. Connect to the network you want to check, by Wi-Fi or cable.
  2. Start netdiag. The interface and address range are filled in for you.
  3. Click Scan and read the tiles: alive, printers, web, mDNS, offline, conflicts.
