## 1. Goal
netdiag opens on a **Help** page. It answers "Is anything wrong?" in one line and offers big buttons for the problems people actually have: the internet is down, a printer won't print, a server can't be reached, the Wi-Fi keeps dropping, a new device needs setting up, or something unknown has appeared. First-time users get a three-step welcome ("You're connected through the router at 192.168.1.1…", then "Check my network", then "Here's what we found"). Technical fields move behind **Advanced**.

Each button leads to a guided check that ends with a verdict, a status word and at most three things to try. **Can I reach it?** tests one server step by step. **Watch my connection** says whether drops start at the Wi-Fi, a device or the internet line. **This computer's printers** finds a print queue pointing at an old address. **Is this ours?** means netdiag only mentions strangers. **Find a new device** points at the thing you just plugged in. Every result can be copied for IT or sent to team chat with a preview. Claude gets matching runbooks for these checks, but cannot mark devices or start the wizard.

## 4. Design
### 4.0 Shared plumbing (extends F4, F6, F7, F8, F10; no new foundation)

**User experience:** none of its own.

**Backend**
- **F4 job kinds and classes** (`internal/service`, in v0.7's job registry):

  | kind | class | limit | origin rules |
  |---|---|---|---|
  | `reach` | light | one at a time | agent: at most one start per 10 s; `repeat` is UI only |
  | `dropping` | singleton | one per computer, outside the two heavy slots | agent: 2 or 10 minutes only |
  | `findDevice` | singleton | sends no traffic of its own | UI only |

  - Reuse v0.7's `Job.Origin` ("ui" | "mcp") and `CancelJob(id, origin)`, which refuses when origin is "mcp" and the job is a UI job.
  - Reuse v0.7's `GET /api/jobs?state=running`, so a reloaded page reattaches.
  - Bus replay ignores unknown event types (`internal/scan/bus.go:48-87`, no default case), so every job keeps its own snapshot for `GET /api/jobs/{id}`.
- **Interface kinds:** add `Kind string` ("ethernet" | "wifi" | "vpn" | "virtual" | "other") to `netinfo.Iface` (`internal/netinfo/rank.go:10-18`).

Move the adapter walk that already exists in `internal/health/dnsservers_windows.go:14-41` into `netinfo` and share it.
  - macOS: name patterns (`utun*`, `ppp*`, `ipsec*`, `gif*`, `stf*`) plus `virtualRe` (`rank.go:20`).
  - `Rank` (`rank.go:25-50`) also drops `vpn` and `virtual` unless nothing else is left. It keeps the default-route interface, but the welcome text then says it is a VPN.

  - `SettingsTriggers.UnknownDevice bool` (default true).
  - `SettingsAlerts.UnknownSkipPrivate bool` (default false).

- **Advice keys (F6):** add catalogue entries keyed on structured fields, never on detail text: `reach.*`, `dropping.*`, `queue.*`, `unknown.*`, `find.*` (listed in each feature).

### 4.1 #15 "Can I reach it?" connection tester (C05)

**User experience**
1. Entry points:
   - Help home **Can't reach a server**.
   - Drawer action row (F5) **Can I reach it?**, pre-filled with the device's address.
2. A dialog `#reach-dialog` titled "Can I reach it?".
   - One box labelled "Shared folder, web address or computer name". The placeholder lives in index.html: `\\server\share, a web address, or a name`.
   - Chips:
     - "Recent" (last 5).
     - **Pick from devices**: name (room) · address from the current scan.
     - For a bare name or address only, "What do you use on it?": **Shared folders** · **Web page** · **Remote desktop** · **Just check it's there** (default).
   - Primary button **Check**.
3. Steps appear one by one, each with shape + word (OK / Problem / Skipped / Checking):
   - **name:** "fileserver is 192.168.1.10". Problem: "This computer can't find 'fileserver'."
   - **route:**
     - "On this local network (Wi-Fi)"
     - "On another network, through the router"
     - "Through your VPN (WireGuard)"
     - Problem: "This address isn't on any network this computer can reach."
   - **ping:** "Answers ping (3 ms)". Skipped: "Doesn't answer ping. Many computers don't; checking the service next."
   - **service:**
     - OK: "File sharing answers".
     - Refused: "fileserver is on, but it isn't accepting file sharing connections. File sharing may be off, or limited to some computers."
     - No answer: "No answer on file sharing. fileserver may be switched off, or a firewall is blocking it."
   - **web:**
     - "The page answers: 'Intranet - Home'".
     - "The page answers with an error (the server says 503: it is having trouble)".
     - "Its certificate expires in 12 days".
     - "This computer doesn't trust the page's certificate".
4. Verdict (`role="status"`): "OK: fileserver works from this computer." or "Problem: fileserver doesn't answer on file sharing." It is followed by **What to try** (up to 3 F6 steps).
   - Buttons:
     - **Tell me when it works**.
     - **Check all services**: only when the target is on the scan interface's network; hands off to the v0.7 port check, Common preset.
     - **Copy for IT**.
     - **Send to chat**: only when chat is connected.
     - **Open remote desktop**: only for a passing Remote desktop check, D12.
   - Caveat line when the route is a VPN or the name resolved outside every local prefix: "Other computers may get a different answer: this one uses a VPN."
   - Proxy line for web targets: "netdiag connects directly, without your browser's proxy settings."
5. **Tell me when it works:** "Trying again every 30 seconds for up to 10 minutes. You can close this box." Progress reads "Try 3 of 20".
   - On success: a polite banner "Works now: fileserver answers on file sharing (10:52)".
   - Optional tick "Also tell the team in chat". It shows the exact message before starting and posts once on success.
   - After 10 minutes: "Still not working after 10 minutes."
6. Esc closes the dialog and returns focus to the trigger. The job keeps running server-side, and reopening reattaches.

**Backend**
- New package `internal/reach`:
  - `type Kind string`: `file_share` (445), `web`, `remote_desktop` (3389, `model.PortRDP` if D12), `presence`.
  - `func Parse(raw string, use Kind) (Target, error)` accepts `\\host\share`, `//host/share`, `smb://host/share`, `http(s)://…`, a bare IPv4 address or a DNS-style name.
    - It rejects IPv6 ("netdiag checks IPv4 addresses only"), spaces and control characters, and more than 255 characters.
  - `func Allowed(a netip.Addr) bool` accepts IPv4 that is private (`a.IsPrivate()`), link-local or CGNAT 100.64/10. It rejects loopback, multicast and broadcast. Under D3-B it also requires a local prefix.
  - `func Run(ctx context.Context, t Target, d Deps, emit func(Step)) Result`. Overall cap 10 s; name 3 s; ping 1 s; TCP 2 s; web 3 s.
  - `Deps{Resolver interface{LookupNetIP(ctx, network, host string) ([]netip.Addr, error)}, Pinger discovery.Pinger, Dial, Refused, Interfaces func() ([]netinfo.Iface, error), SourceFor func(netip.Addr) (netip.Addr, error), Web func(ctx, *url.URL, netip.Addr) model.WebService, Now}`.
  - The resolver is `net.DefaultResolver`: GetAddrInfoW on Windows (DNS, LLMNR, NetBIOS, .local), libSystem on macOS. There is no mDNS socket of netdiag's own.
  - **Route:** if the address is in a local interface prefix, the route is "local" with that interface's Kind. Otherwise `SourceFor` uses `net.DialUDP("udp4", nil, target:9)` and reads `LocalAddr()`, which sends nothing. That maps to the interface, so the route is "vpn" or "router".
  - `Step{ID: name|route|ping|service|web, Status: ok|problem|skipped|checking, Says, Detail, Ms}`.
  - `Result{Target, Resolved []string, Route{Kind, Iface}, Steps, FailedAt, Verdict advice.Advice, CheckedAt}`.
- `internal/portprobe/web.go`: add `ProbeURL(ctx, u *url.URL, ip netip.Addr) model.WebService`.
  - It dials `ip` but keeps the Host header and SNI. `ProbeWeb` (`web.go:31-80`) always uses the IP as host.
  - Same-host redirects only, the 256 KB body cap, `Proxy` nil.
  - It adds `TLSInfo.Trusted *bool` from `x509.Certificate.Verify(VerifyOptions{DNSName: host})` with system roots, plus days-left from `certInfo` (`web.go:143`).
- `internal/service/reach.go`:
  - `StartReach(ctx, ReachRequest{Target, Use string; Repeat, ChatOnSuccess bool}, origin string) (string, error)`, with `origin` one of v0.6's `model.OriginUI` and `model.OriginMCP` (master roadmap v0.6-D48).
  - Errors: `ErrNotPrivate`, `ErrRateLimited{RetryAfter}`, `ErrBusy{ID}`.
  - Repeat runs at most 20 attempts 30 s apart and stops on the first OK.
- Advice keys: `reach.name`, `reach.no_route`, `reach.refused`, `reach.no_answer`, `reach.web_error`, `reach.cert_untrusted`, `reach.cert_expiring`, `reach.ok`.

**API** (session token required on POST; `Content-Type: application/json` per `internal/server/guard.go:11-26`)
- `POST /api/checks/reach` with `{"target":"\\\\fileserver\\scans","use":"file_share","repeat":false,"chatOnSuccess":false}`:
  - `202 {"id":"j-…"}`
  - `400 {"error":"This checks servers on your own networks only.","code":"notPrivate"}`
  - `409 {"error":"A check is already running.","id":"j-…"}`
  - `429 {"error":"Wait a few seconds before the next check.","retryAfterSec":7}`
- `GET /api/jobs/{id}` → `{id, kind:"reach", state, origin, startedAt, progress{elapsedSec,totalSec}, attempt{n,of,nextAt}, result}`.
- SSE `GET /api/jobs/{id}/events`: `reach_step` (Step), `reach_attempt {n, of, ok}`, terminal `done {result}`. A reconnecting client fetches the snapshot first.
- `POST /api/jobs/{id}/cancel` → `204`.
- Share: `POST /api/chat/share {"kind":"reach","jobId":"j-…"}`.

**UI**
- index.html: add `<dialog id="reach-dialog" aria-labelledby="reach-h">` after `#settings-dialog` (`web/index.html:460`). Add a drawer action-row button and a Help home button.
- app.js: `reach{open, target, use, job, steps, verdict, recent}`, plus `openReach(prefill)`, `startReach()`, `reachSubscribe(id)`, `reachRetry()`, `closeReach()`.
- **No `http(s)://` literal anywhere in app.js** (`internal/server/static_test.go:47-53`). URL hints and parsing stay server-side.
- styles.css: v0.7's `ol.checksteps`, using tokens only (never a global `.steps` rule, which would restyle every "What to try" list).
- Icons in `tools/icons/icons.txt`: `i-route route`, `i-timer timer`. Each step status gets its own shape: circle-check, circle-x, circle-dot, clock.

**Persistence:** none server-side. Recent targets go in `localStorage['netdiag.reachRecent']` (5 entries, inside try/catch).

**MCP**
- `test_connection` (probeAnn) with `{target, use?}`. It waits up to 12 s and returns `{target, kind, resolved[], route, steps[], verdict{failedAt, sentence, steps[], actions[]}}`.
  - Rate limit: one start per 10 s, answered "wait N seconds".
  - It can never repeat. Add `Repeat: true` to the authority `forbidden` substrings for mcpserver non-test files.
- `get_check {id}` (readAnn) → job snapshot.
- `cancel_check {id}` (same annotation as `cancel_scan`) → only agent-started jobs. Otherwise it answers "That check was started in the netdiag window; stop it there."

**bubbles:** share kind `reach` posts a message, never an alert:

> Can I reach it? from RECEPTION-2 at 10:42: fileserver (192.168.1.10). Name: OK. Route: on another network, through the router. Ping: OK. File sharing: no answer (switched off, or blocked by a firewall).

With `chatOnSuccess`, one post on success: "fileserver answers on file sharing again (checked from RECEPTION-2 at 10:52)."

**Platform/Defender**
- One target, started by the person, outbound only, rate-limited, no child process, no new listening socket, so no firewall prompt.
- Reaching beyond the local subnets is new (D3).
- macOS: Terminal-launched binaries are exempt from Local Network privacy (TN3179). Check a Finder-launched case in M9.

### 4.2 #18 "Is it dropping?" connection watch (C06, on demand)

**User experience**
1. Health view, new section `#dropping` under the cards: heading "Is it dropping?" with "Watch the connection for a few minutes to see where drops start."
   - Radios: **2 minutes** / **10 minutes** (default) / **30 minutes**.
   - "Also watch a device": None, or named devices from the scan.
   - Checkbox "Also check the internet line" (default on). If the last internet check failed it is off, with "Your internet check isn't answering right now, so only the router is watched."
   - Primary **Watch my connection**.
   - Also reachable from Help home **Wi-Fi keeps dropping**, and from the drawer action row **Watch its connection**. That label is different from v0.8's **Watch this device**.
2. While running:
   - "Watching: 4:12 of 10:00" with **Stop**.
   - A chart with rows Router / <device name> / Internet, at most 60 columns: a filled square means all answered, × means some lost, hatched means the computer was asleep.
   - A text line every 10 s: "Router: no drops · Internet: lost 3 checks at 2:14 pm".
   - On Wi-Fi: "Wi-Fi signal 62% · 5 GHz", marking "weak signal", "dropped to 2.4 GHz" and, on Windows only, "moved to another access point".
   - Screen readers get a polite summary every 30 s, plus a `<table class="sr">`.
3. Verdict (examples):
   - "Problem: The drops start at the Wi-Fi. Lost 8% of checks to the router between 2:10 and 2:25 pm, while the signal was 31%." What to try: "Move closer to the router, or try a cable."
   - Wired: "Problem: The drops start between this computer and the router. Check the cable and try another socket on the router."
   - "Problem: The drops are beyond your router: the internet line." What to try: "1) Restart the modem (unplug it for 30 seconds). 2) If it keeps happening, call your internet provider and give them these times: 2:10 pm, 2:14 pm."
   - "Problem: Only Front desk printer drops: that device or its Wi-Fi."
   - "OK: No drops in 10 minutes. If it happens at a particular time, run the 30-minute watch then."
   - Sleep: "This computer was asleep from 2:16 to 2:21 pm; those minutes aren't counted."
   - Buttons: **Send summary to chat**, **Copy for IT**, **Watch again**.

**Backend**
- New package `internal/connwatch`: `Run(ctx, Opts, emit func(Update)) Result`.
  - `Opts{Gateway netip.Addr; GatewayTCP []int; Device *Target{IP netip.Addr; TCPPort int}; Internet *HostPort; Duration; Pinger discovery.Pinger; Dial; WiFi func(ctx) (health.WiFiInfo, error); WiFiEvery; Now}`.
  - Every second: ping the router and the device concurrently (900 ms timeout). Every 5 s: a TCP connect to the internet host on 443 (2 s timeout), with no bytes sent. Wi-Fi every 5 s on Windows and every 30 s on macOS, because `readWiFi` on macOS runs `system_profiler` (`internal/health/wifi_darwin.go:10-18`).
  - Wi-Fi is read through `health.NewRunner().WiFi`, an exported field filled in `defaults()` (`internal/health/health.go:115`). That skips the 60 s cache, which lives only in `checkWiFi` (`health.go:363-374`). BSSID exists on Windows only (`wifi_windows.go:169`); `parseSystemProfiler` (`internal/health/parse.go:116`) reads none.
  - Devices that ignore ping (no `icmp` in `FoundBy`) are dialled on the port picked by the v0.5.7 `presencePort` rule, which never uses remote-access ports. Export it as `scan.PresencePort`. A router that ignores ping uses 80/443 like the v0.5.7 gateway fallback.
  - `Stats{Sent, Lost, LossPct, MedianMs, P95Ms, JitterMs, LongestOutageSec, Outages[]}` per target.

All rows go into the v0.6 runbook registry in `internal/mcpserver/prompts.go` (today `PromptNames` at `:14`, `registerPrompts` at `:20`), with footer v2. Arguments are optional, and the runbook asks when one is blank. Bold labels must exist in `web/index.html`, `web/app.js` or `advice.ActionLabels()` (server-built buttons such as **Open Printers settings**), enforced by `TestRunbookButtonsExist`. No "event", "venue" or bare "LAN".

**`cant_reach_server`: "Can't reach a server"**
- **Purpose:** find which step fails when this computer can't reach a server, shared folder, website or remote desktop.
- **Args:** `target` (optional).
- **Steps:**
  1. With no target, ask what they type or click (`\\server\share`, a web address, a computer name).
  2. Call test_connection: one check of up to about 10 seconds to one address. If it answers notPrivate, say netdiag checks only servers on their own networks, and for websites use internet_not_working.
  3. Read the steps in order (name, route, ping, service, web) and stop at the first failure:
     - name: check the spelling; connect the work VPN if they use one; otherwise ask IT.
     - route "router" or "vpn": it is on another network.
     - ping skipped is fine.
     - service with no answer: "switched off, or blocked by a firewall"; never pick one.
     - web: status and certificate.
  4. Call list_devices with that query; if the device is offline, use device_offline.
  5. If every step passes, it works from this computer, so the problem is the other computer or its login.
  6. In the window: **Can I reach it?**, then **Tell me when it works**. **Check all services** is a port check you cannot start. For Remote desktop: **Open remote desktop**.
- **Tools:** test_connection, list_devices, get_status.
- **Test:** `{"cant_reach_server", nil, {"test_connection","name","route","ping","service","switched off, or blocked by a firewall","Can I reach it?","Tell me when it works","notPrivate"}}`.

**`connection_dropping`: "Connection keeps dropping"**
- **Purpose:** watch the connection for a few minutes and say whether drops start at the Wi-Fi, a device or the internet line.
- **Args:** `minutes` (optional, 2 or 10, default 10), `device` (optional).
- **Steps:**
  1. Call check_internet once. If something is down now, explain it as in internet_not_working and stop.
  2. Say you will watch for N minutes with one small check per second to the router (and the device). Ask them to work normally and tell you when a drop happens.
  3. Find the device's ip with list_devices. Call start_connection_watch and keep the id.
  4. Call get_check every 30 seconds with short updates. cancel_check if they want to stop.
  5. Read the verdict: router means Wi-Fi or cable; beyond the router means the internet line ("restart the modem; then call your provider with these times"); weak signal means Wi-Fi coverage; device-only means that device; none means "No drops in N minutes".
  6. Mention any sleep gap.
  7. For 30 minutes, it is **Watch my connection** in **Health**, then **Send summary to chat**.
- **Tools:** check_internet, list_devices, start_connection_watch, get_check, cancel_check.
- **Test:** `{"connection_dropping", nil, {"check_internet","start_connection_watch","get_check","cancel_check","Watch my connection","Health","router","provider"}}`.

**`review_unknown_devices`: "Is this device ours?"**
- **Purpose:** go through devices nobody has marked as ours and help decide what each one is.
- **Args:** none.
- **Steps:**
  1. Get the scanId from get_status. Call list_devices filter=unknown, following nextCursor. If there are none: "OK: every device here is marked as ours."
  2. If more than 10 and the person says everything here now is theirs: **Mark everything here now as ours**. Stop.
  3. For at most 10 per round, call get_device and sort into: privateAddress ("a phone or laptop using a private Wi-Fi address; its maker is hidden on purpose"); recognisable from type, vendor, mDNS name or web title; can't tell. Give first seen.
  4. For each one: **Yes, it's ours** (then **Name this device**), or **I don't recognise this**. You cannot mark devices yourself.
  5. An unknown device is not dangerous by itself. If nobody claims it, changing the Wi-Fi password is the simple fix. Never call it an intruder. Never suggest blocking it yourself.
  6. If chat is connected: **Ask the team in chat**.
- **Tools:** get_status, list_devices, get_device.
- **Test:** `{"review_unknown_devices", nil, {"filter=unknown","privateAddress","Mark everything here now as ours","Yes, it's ours","I don't recognise this","You cannot mark devices yourself","not dangerous by itself"}}`.

**`set_up_new_device`: "Set up a new device"**
- **Purpose:** spot a newly plugged-in printer, camera or TV, then open its setup page, name it and watch it.
- **Args:** `what` (optional).
- **Steps:**
  1. Ask them to click **Find a new device** in **Devices**, then plug in or switch on the device. You cannot start it yourself.
  2. Every 15 seconds, call get_status and read findDevice (phase, secondsLeft, found). A device can take about 30 seconds to appear.
  3. If this connection shares the window and netdiag is watching, you may follow get_events for new host entries.
  4. When found, call get_device: "Found it: <maker model> at <ip>". On the card: **Open its page**, **Name it**, **Watch this device**.
  5. If phase is nothing: "It may not have got an address: check its cable, or set it to get its address automatically." Guest Wi-Fi hides it.
  6. For a printer, offer check_printer.
- **Tools:** get_status, get_events, get_device, check_printer.
- **Test:** `{"set_up_new_device", nil, {"Find a new device","findDevice","get_events","Open its page","Name it","Watch this device","automatically","You cannot start it yourself"}}`.

## 9. Risks and mitigations
| Risk | Mitigation |
|---|---|
| Release is large (2 L + 4 M) and slips | Independent milestones (M2-M6). #12 last, with buttons hidden until their check exists. D14 offers a 0.9.1 split for the macOS printers reader only |
| winspool struct marshalling bugs, especially arm64 | Struct-size tests per arch; fuzz-free fixed buffers; test on windows/arm64 in M9 |
| `EnumJobsW` on a print-server connection hangs | Click-only; 3 s per queue in a goroutine; "the print server didn't answer" |
| Registry ACL differs on managed PCs | Fallback text "netdiag can't read where this printer sends"; XcvData kept as a later fallback |
| Refused vs no answer misread as off vs firewall | Wording always names both; refused only proves the device is on |
| VPN or split DNS gives different answers on other PCs | Route step names the VPN; caveat line on the verdict |
| Reaching other private networks looks like reconnaissance to EDR | One target, user-started, private only, one at a time, agents one per 10 s, 20 retries max; port check hand-off only for the local network (D3) |
| 30-minute raw-ICMP ping on Windows looks unusual to Defender | IcmpSendEcho2 (D9); Defender check in M9; submit the release as a false positive |
| Sleep or stalls skew loss | Wall-clock gap detection, marked and excluded |
| macOS hides Wi-Fi details and has no BSSID | Plain "details hidden" text; roam detection Windows-only |

## 10. Decisions needed
1. **D1 Landing view.** Open on Help every launch, or only on first run and then remember the last view? Options: (A) always Help; (B) first run, then last view; (C) a setting. **Recommend B.** Pressing Scan switches to Devices.
2. **D2 Navigation budget.** A separate Help view (breaks the nav-count and views guards, more screenshots) or Help inside Devices? **Recommend a separate view.** The guard updates are planned in M7.
3. **D3 Can I reach it? scope.** (A) private, link-local and CGNAT addresses on any network (VPN, other office), one target at a time; (B) only this local network. **Recommend A** with the listed limits. The port-check hand-off stays local-only.
4. **D4 Stuck print jobs.** Offer to cancel the user's own jobs (no admin needed) or stay read-only? **Recommend read-only in v0.9** plus **Open Printers settings**. Revisit with CUPS auth testing.
5. **D5 Unknown device severity in chat.** Info or warning? **Recommend info**, matching bubbles docs for newDevice.
6. **D6 Known list scope.** Per network fingerprint or global? **Recommend** flags per MAC (global), but alerts only on networks that have a known list. This answers part of "one site or many".
7. **D7 Private-address phones.** Default for "Don't tell me about phones using private addresses": off or on? **Recommend off**, with the checkbox visible.
8. **D8 Watch length.** Is a 30-minute maximum enough, or "all afternoon"? **Recommend 30 minutes.** Longer runs belong with the backlog background monitor.
9. **D9 Windows pinger.** Use IcmpSendEcho2 for the connection watch (S-M), or keep pro-bing raw sockets? **Recommend IcmpSendEcho2 for connwatch only in v0.9.** Measure before switching discovery.
10. **D10 Find device speed.** Normal 15-second cadence, plus one immediate cycle, or faster checks for 5 minutes? **Recommend** normal cadence plus `CycleNow` once. No faster sweeps before signing.
11. **D11 MCP authority.** Adopt §4.7 (agents may start `test_connection`, 2- or 10-minute watches and `list_local_printers`; everything else UI-only)? **Recommend yes.**
12. **D12 Remote access: RESOLVED.** It shipped in v0.5.7. #15 shows **Open remote desktop** after a passing Remote desktop check and reuses `model.PortRDP` and the existing `POST /api/scans/{id}/remote` route.
13. **D13 Critic's "move the cheap first-run parts earlier".** If v0.7 adds interface kinds for port-scan scoping, M1 reuses them and #12 shrinks. Otherwise keep everything in v0.9. **Recommend no earlier move** beyond what v0.7 needs.
14. **D14 Release split.** Keep everything as v0.9.0, or ship the macOS printers reader in 0.9.1 if it slips? **Recommend one release.** Allow the 0.9.1 fallback for the macOS reader only, said plainly in the notes.

## 13. Microsoft Store readiness (rest of 0.9.x) and the v1.0.0 Store release

> **Decided by the product owner, 2026-10-17.** netdiag goes to the Microsoft Store. The work to get there is the **final part of the 0.9.x series**, and the first Store release is **v1.0.0**. Sections 1-12 above are v0.9.0 ("Fix it yourself"). This section covers v0.9.1 and later, up to v1.0.0. The researched background, sources and costs are in [signing-and-store.md](signing-and-store.md).

### 13.1 Route

- **Store route: MSIX.** Ship an MSIX package (one `.msixbundle` for x64 and arm64), which Microsoft signs, hosts and updates. Do not use the EXE/MSI installer route: it needs a certificate from Microsoft's Trusted Root Program, and Azure Artifact Signing is listed as **not eligible** for it.
- **Signed GitHub zips (recommended, separate track).** Azure Artifact Signing ($9.99/month; individuals in the US/Canada; ID check) signs `netdiag.exe` in the GitHub zips. This can start any time before v1.0.0. It is not required for the Store.
- **Version numbers.** MSIX versions can't start with 0, so v1.0.0 is also the first Store version (MSIX `1.0.0.0`). GitHub releases move to 1.0.0 at the same time, so both channels show one version.
- **Data.** The Store copy and the zip copy keep separate data, because MSIX redirects `%AppData%`. Document this; offer settings export/import later if users ask for it.

### 13.2 Scope

| Item | Type | Size |
|---|---|---|
| Windowless Start-menu app (`netdiag-app.exe`, `-H=windowsgui`): errors shown in the browser page or a message box, never in a console | Feature | M |
| Command alias so `netdiag` (console) still works from a terminal, including `netdiag mcp` for Claude | Foundation | S |
| A way to quit and stay running: v0.6's single instance (F9) plus either a **tray icon** or **exit when the last tab closes** (decision 13.6-1) | Feature | M |
| Privacy policy page `docs/privacy.html` (Store policy 10.5.1): no telemetry, data stays on this computer, what is read from the local network and Wi-Fi, the optional internet check | Docs | S |
| MSIX manifest (`runFullTrust`, command alias, location capability for Wi-Fi details), Store logos and tile assets from the existing icon | Foundation | M |
| `scripts/package-msix.ps1`: builds `.msixbundle` (x64 + arm64) with MakeAppx from the Windows SDK; CI job on a Windows runner; package version derived from the tag | Foundation | M |
| Packaged-app checks: Wi-Fi Location prompt, Windows Firewall prompt, Remote Desktop launch, history and settings location, quit and reopen, Windows App Certification Kit (WACK) | Tests | M |
| Store listing text (plain, no URLs), screenshots, notes for testers, age rating answers | Docs | S |
| Microsoft Defender false-positive submission of the exact exes that go into the package, before the Store submission | Release | S |
| "Get it from Microsoft" badge on the site and README after it goes live | Docs | S |

Out of scope for v1.0.0: the macOS App Store (the Mac build gets Developer ID notarization instead, if the owner joins the Apple Developer Program), the winget listing (follows v1.0.0), and paid features.

### 13.5 Risks

| Risk | Mitigation |
|---|---|

### 13.6 Decisions needed

1. **Tray icon or exit when the last tab closes?** The tray keeps monitoring and alerts running with the tab closed (needed by v0.8 "Keep watching"). Exit-on-close is simpler. **Recommendation:** tray, if a CGO-free library works on windows/arm64; otherwise exit-on-close.
2. **Signed GitHub zips before v1.0.0?** **Recommendation:** yes, start Azure Artifact Signing during 0.9.x so v1.0.0 zips show a verified publisher.
3. **Fallback Store name**, for example "netdiag network check".
4. **Mac notarization for v1.0.0** ($99/year Apple Developer Program)? It removes the Terminal step for Mac users.
