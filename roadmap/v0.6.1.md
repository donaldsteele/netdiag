# netdiag v0.6.1 "Tailnet": plan

> **Status, 2026-11-21.** Product owner request: show the computers on this computer's Tailscale tailnet, how traffic reaches each one, Tailscale's own health, alerts in live mode, and Claude access. It ships as a point release on top of v0.6.0, before v0.7 (decision PO-8 in [README.md §12.1](README.md#121-product-owner-and-cross-version)). Built on the v0.6 branch head `4d4aa25`.

## 1. Goal

Someone who uses Tailscale opens netdiag and sees their tailnet: this computer in the middle, every other device around it, which ones are online, and whether traffic goes straight to a device or through a Tailscale relay. A Tailscale card on the Health view says whether Tailscale itself is fine. In live mode netdiag says when Tailscale stops on this computer, when a tailnet computer goes offline, or when a device key is about to expire, through the same alerts and team chat as everything else. Claude can read the tailnet and ping one device.

## 2. Scope

| Item | Notes |
|---|---|
| `internal/tailscale` | Reads the local Tailscale service's LocalAPI over local IPC only: the named pipe `\\.\pipe\ProtectedPrefix\Administrators\Tailscale\tailscaled` on Windows (opened for identification, no child process), the Unix socket or the app's port and token on macOS. `Status` and `Ping` (one device, 10 s cap). Read-only: never changes Tailscale. |
| `GET /api/tailnet`, `POST /api/tailnet/ping` | §4. The POST needs the session token. Ping is rate-limited per device. |
| **Tailnet** view | New nav item, shown only while Tailscale is on this computer. A map (this computer in the middle, devices around it, the line style shows the path), then a list with **Check path** per device. |
| Tailscale card on **Health** | Below the six check cards, only while Tailscale is on this computer. Not a seventh pill: the strip stays at six. |
| Alerts | `tailscaleDown`, `tailnetDeviceOffline`, `tailnetKeyExpiring` (§5), each with its own switch in Settings > Alerts, advice, a severity, team chat text, a Problems right now item and a restart rule. |
| MCP | `get_tailnet` (read) and `ping_tailnet_device` (probe). 16 tools become 18. |
| Docs | README "Tailscale" section, docs/mcp.md, site section, field checklist §6 "Tailnet (v0.6.1)", screenshots from mock data only (no real tailnet names). |

**Out of scope.** Changing Tailscale settings, exit nodes or routes. Scanning tailnet addresses with the network sweep (Tailscale adapters stay out of the interface list: `netinfo/rank.go` `virtualRe`). Alerting on relayed paths: a relay is normal Tailscale behaviour and would be noisy; the map shows it instead.

## 3. Privacy

Personal tailnets report the tailnet name as the owner's email address. netdiag never shows or sends it: the API, UI, alerts, chat and MCP name the tailnet by its MagicDNS suffix (`tail1234.ts.net`). Screenshots, docs and tests use invented names only.

## 4. API contract

`GET /api/tailnet` (no session token, like the other reads):

```json
{
  "state": "running",            // running | stopped | needs-login | not-installed
  "version": "1.90.0",
  "suffix": "tail1234.ts.net",   // "" when MagicDNS is off
  "magicDNS": true,
  "self": Device,                // null unless running
  "devices": [Device],           // online first, then by name
  "health": ["..."],             // Tailscale's own warnings, its words
  "card": HealthCheck,           // id "tailscale", label "Tailscale", status word + detail + advice
  "checkedAt": "2026-11-21T12:00:00Z",
  "adminTarget": "https://login.tailscale.com/admin/machines"  // built on the server (no URL literals in app.js)
}
```

`Device`: `{id, name, dnsName, os, ips[], online, active, lastSeen, path, endpoint, relay, keyExpiry, exitNode, exitNodeOption, subnetRoutes[], tags[], keyExpiresSoon, phone}`. `path` is `direct` (with `endpoint`), `relayed` (with `relay`, a DERP region code such as `nyc`), `idle` (online, no traffic lately, so no path yet) or `offline`. `phone` marks iOS and Android devices (never alerted as offline). `keyExpiresSoon` is true within 7 days.

`POST /api/tailnet/ping` `{"ip": "100.64.12.34"}` → `{ip, name, ok, error, latencyMs, path, endpoint, relay}`. Only Tailscale addresses (100.64.0.0/10, fd7a:115c:a1e0::/48). 429 with `{"error": ...}` when the same device was pinged less than 5 s ago (or more than 1 ping per second overall).

## 5. Alerts

| Trigger (settings `alerts.triggers.*`) | Key | When | Fixed when | Severity | Default |
|---|---|---|---|---|---|
| `tailscaleDown` | `tailscaleDown` | Tailscale was running at the start of watching and now is stopped or needs a login (seen twice) | running again (twice) | warning | on |
| `tailnetDeviceOffline` | `tailnetDeviceOffline\|<device id>` | a tailnet device that is not a phone or tablet goes from online to offline (seen twice) | online again | warning | on |
| `tailnetKeyExpiring` | `tailnetKeyExpiring\|<device id or self>` | this computer's key, or a device's, expires within 7 days | key renewed (expiry later than 7 days) or the device is gone | warning | on |

None is held by the storm guard: Tailscale state is read locally. After a restart, `Reconcile` closes them when the condition is gone (`notify/reconcile.go` `gone()`).
