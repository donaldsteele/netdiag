## 1. Goal
Open any device and do something about it. **Check again now** re-checks it on the spot. **Open its page** opens its own settings page, and **Copy for IT** copies a tidy summary. **Name this device** gives it a name and a room, which every list, alert, report and chat message then uses. **Check open ports** shows in plain words which services one device offers. **Wake this computer** wakes a sleeping computer and says whether it came back. **Why won't it print?** gives one plain answer for a printer, and **Make it beep** helps find the right box. **Check my connection** walks from this computer to the internet and says where the connection stops. Anything on screen can be sent to team chat after a preview that shows exactly what will be posted.

### 4.2 F13 Safe port dialing (foundation)

- **New `internal/portprobe/pace.go`:** `type Pacer`, `NewPacer(rate, burst, perHost int)`, `(*Pacer).Dial(ctx, ip string, port int, timeout time.Duration) (net.Conn, error)` and `SetGateway(ip string)`.
  - `Dial` waits for a token, takes a per-host slot, then calls `Dial` (`dial.go:18`).
  - Limits: 32 workers per host by default. The gateway gets 8 workers and half the rate.
- **One bucket for the whole process.**
  - The token bucket moves out of `internal/discovery/discovery.go:144-187` into `portprobe` as `Bucket`.
  - `discovery.Sweep` keeps its 500/s setting but draws from the shared bucket (`portprobe.Shared()`). The sweep, presence, port checks and wake verification together never exceed 500 connects per second.
  - Port checks have their own sub-limit of 300/s.
- **`ScanPorts`** (`internal/portprobe/tcp.go:15-34`) keeps the v0.5.8 worker bound and dials through the shared pacer.
- **Users:**
  - the port check
  - the #8 print-port check
  - wake verification
  - the v0.8 TCP-9 nudge
  - the v0.9 reach and connwatch checks
- **Tests:**
  - `TestPacerRate`, with a fake clock: no more than the configured rate per host, and half for the gateway.
  - `TestPacerPerHostCap`.
  - `TestSweepSharesBucket`.

### 4.3 F4 Check-job registry (foundation)

**Backend (`internal/service/jobs.go`):**

```go
type Origin string // "ui" | "mcp"
type JobClass int  // Light, Heavy; v0.9 adds Singleton
type Job struct{ ID, Kind, State, Target string; Origin Origin; StartedAt, FinishedAt time.Time }
func (s *Service) StartJob(kind, target string, origin Origin, run func(ctx context.Context, emit func(model.Event)) (any, error)) (string, error)
func (s *Service) Job(id string) (JobSnapshot, bool)
func (s *Service) Jobs(state string) []Job
func (s *Service) CancelJob(id string, origin Origin) error // refuses mcp on a ui job
```

- **Per-job bus.** Each job has its own `scan.NewBus()` (`internal/scan/bus.go:30`) for SSE. The bus replay keeps only known event types (`bus.go:42-95`), so each job also keeps its own snapshot.
- **Limits.**
  - Heavy (`portscan`): 2 in total, 1 per address.
  - Light:
    - `internet`: 1 at a time
    - `printer`: 1 per printer
    - `wake`: at most 3, and 1 per MAC
  - A full limit returns 409 with the running job's id. Rate limits return 429 with `retryAfterSec`.
- **Separate from scans.** Jobs are separate from `Registry`'s one-scan rule (`internal/scan/registry.go:42-60`). A job never starts, cancels or replaces a scan, so the v0.6 ReplaceLive guard is untouched.
- **Lifetime.**
  - Finished jobs are kept for 10 minutes, at most 20.
  - Jobs end on Quit through the v0.6 `svc.Close`.
- **Errors:** add `ConflictError` and `TooManyError` next to `BadRequestError` and `NotFoundError` (`internal/service/service.go:21-28`), and map them in `svcErr` (`internal/server/handlers_v2.go:25-39`).

**API:**
- `GET /api/jobs/{id}` → `{id, kind, state:"running|done|cancelled|failed", origin, target, startedAt, finishedAt, progress:{done,total,etaSec}, result}`.
- SSE kind events: `portscan_port`, `internet_step`, `printer_step`, `wake_phase`. A client that reconnects fetches the snapshot first.

**UI:**
- `init()` (`web/app.js:95`) calls `GET /api/jobs?state=running` and reattaches the drawer, Health and wake progress.
- A shared `.steps` list style goes in styles.css. v0.9 reuses both the reattach and the style.

**MCP:** `check_internet` and `check_printer` start jobs with origin `mcp` and wait for them. There is no generic job tool until v0.9 (`get_check`, `cancel_check`).

### 4.4 F5 Drawer action row and re-probe (foundation)

**User experience:**
- A row `<div class="actions" id="drawer-actions">` sits under `.drawerhead` (`web/index.html:244-251`). Each button has its icon and text on one line, and the row wraps.
- Buttons:
  - **Check again now**
  - **Open its page**
  - **Copy for IT**
  - **Name this device**
  - **Check open ports**
  - printers only: **Why won't it print?** and **Make it beep**
  - eligible offline computers only: **Wake this computer**
  - only when chat is connected: **Send to chat**
- The **Remote access** section stays where it is (`#drawer-remote`). The row never repeats **Open remote desktop**.
- **Check again now** shows "Checking 192.168.1.50…", then "Checked 10:42: answers" or "Checked 10:42: still not answering".

**Backend: `POST /api/hosts/{ip}/probe {"scanId":"…"}` (token).**
- The address must be IPv4 on a local interface subnet (`ErrNotLocal`, `internal/scan/probe_host.go:18, 50-63`).
- At most 1 per address per 5 s (429).
- **During a live scan that holds the host:** the new `Scan.Reprobe(ctx, ip) (model.Host, error)` hands the IP to the live goroutine through a channel.
  - The live goroutine runs the runner's own `probe` (`internal/scan/orchestrator.go:733`) plus one presence check through `presenceUpdate` (`internal/scan/live.go:425`).
  - It stamps `reprobeAt` (`live.go:273-285`) so the live cycle does not probe the same host at the same moment.
  - The row, the online counters and the v0.6 notify engine all see the result, so a device that answers again gets its Fixed notice.
- **Otherwise:** `Service.ProbeHost` (`internal/service/probe.go:13`) runs as today: an isolated runner that saves nothing.
- Response: 200 `{"host":{…},"updatedLiveScan":true}`.
- v0.8 extends the route to a watched device's `lastIP` that is not in the host map.

**MCP:** `probe_host` takes the same path, and its output gains `updatedLiveScan` (V7-D9).

### 4.5 F8 Inventory store, private addresses and `names.Best` (foundation)

**Package `internal/inventory`:**

```go
type Record struct{ Name, Room, Owner, Notes, CreatedAt, UpdatedAt string; LastWake *model.WakeResult; PortScan *model.PortScanResult }
type File struct{ SchemaVersion int; Devices map[string]Record } // schemaVersion 1
func Key(h model.Host) string // arp.NormalizeMAC upper-case MAC, else "ip:"+IP
func Open(dir string) (*Store, error)
func (s *Store) Lookup(key string) (Record, bool) // scan.Deps reader
func (s *Store) Put(key string, r Record) (Record, error)
func (s *Store) SetLastWake(key string, w model.WakeResult) error
func (s *Store) SetPortScan(key string, p model.PortScanResult) error
func (s *Store) Snapshot() File
```

- **Single writer.**
  - One `*inventory.Store` per process, created in `cmd/netdiag/ui_cmd.go` next to `store.Open` (`:32`) and the v0.6 ledger.
  - It is passed to both `scan.Deps.Inventory` and `service.Config.Inventory`. This avoids the two-Store problem (`internal/scan/integrate.go:87` opens a second store).
  - The CLI scan command gets a read-only instance.
- **Saving.**
  - Writes use the atomic write (`internal/store/store.go:78`) and are debounced to 1 s.
  - On a Windows sharing violation (Defender holding the file), one retry after 200 ms.
  - A missing file means empty. An unreadable file is renamed `devices.json.bad-<time>`.
- **Key.**
  - The upper-case MAC, also for private addresses (which get a warning). Without a MAC: `ip:<ip>`.
  - An `ip:` record moves once to the MAC key the first time that host has a MAC. This is the only re-key.
- **Writer: `Service.SaveDevice(key string, in model.DeviceInfo) (inventory.Record, error)`.**
  - Text is trimmed. Name, room and owner can be up to 60 characters, notes up to 500. Control characters are rejected.
  - Saving with every field empty deletes the record.
  - The change reaches a running scan through a new state op, `applyInventory`, modelled on `applySettings` (`internal/scan/analyze.go:104-114`) and reached through `Scan.ApplyInventory`, like `Scan.ApplySettings` (`orchestrator.go:306`).
- **New `model.Host` fields** (`internal/model/model.go:43`): `Label`, `Room`, `PrivateAddress` and `NameSuggestion`, all `omitempty`.
  - `Label` and `Room` come from `Deps.Inventory.Lookup` in `state.mutate` (`internal/scan/state.go:78`).
  - `PrivateAddress` = `mac[0]&0x02 != 0`. It is set wherever the MAC is set: the ARP harvest and the live ARP read (`live.go:238-260`). `Vendor` is never overwritten.
  - `NameSuggestion` comes from SNMP sysName and sysLocation, or the mDNS instance.
- **`names.Best(h model.Host) string`** (new `internal/names`): `Label`, then the mDNS instance (F14 `Details`), then SNMP sysName, then `Hostname`, then printer model, then IP.
  - It replaces `label()` (`internal/notify/notify.go:100`) and the v0.6 chat-title chain.
  - Users: the table, drawer title, Problems card, chat titles, F12 text, the v0.8 diff sentences and report, and MCP.

**API:**
- `GET /api/inventory` (read-only, no token, like the scan snapshot) → `{"schemaVersion":1,"devices":{"3C:52:82:11:22:33":{"name":"Front desk printer","room":"Reception",…}}}`.
- `PUT /api/inventory/{key}` (token), body `{name, room, owner, notes}`:
  - 200: the record
  - 400: `{"error":"Names can be up to 60 characters."}`
  - 404: the key is in no scan and no record

**MCP:**
- Read-only, through the Host fields.
- `get_device` gains `inventory{name, room, owner, notes}` through `Service.DeviceInfo`, so mcpserver never imports `internal/inventory`.
- `SaveDevice(` is forbidden.

### 4.7 Port check: **Check open ports** (feature)

**User experience:**
1. **Check open ports** (`i-scan-eye`) in the action row opens a short radio list:
   - **Common services** (default): "about 100 well-known services, about 2 seconds"
   - **Printer**
   - **Camera**
   - **Remote access**
   - **File sharing**
   - **First 1,024 ports**: "about 5 seconds, up to 30 if the device stays silent"

   Help text: "netdiag opens and closes a connection to each service on this device, and reads web pages the way your browser does. It never logs in." Button: **Check**. Esc closes the list and returns focus to the button.
2. Progress (`role="status"`): "Checked 412 of 1,024 · about 6 s left", with **Cancel**. The `<progress>` element has no animation.
3. Results go in `<section id="drawer-ports"><h3>Open ports</h3>`, headed "Checked 10:42 with Common services".
   - Answering ports come first, each with shape, word and one plain line:
     - "443 Secure web page" with **Open its page**
     - "445 File sharing: this device shares folders"
     - "9100 Printing"
     - "23 Telnet: old and unsafe; turn it off if nobody uses it" (V7-D12)
     - 22, 3389 and 5900: "Remote access: see Remote access above", linking to `#drawer-remote`. There is no second open button.
   - Then counts: "1,010 closed (the device is on, but offers nothing there) · 14 no answer".
   - "No answer" reads "blocked or filtered" when the device answered other ports, otherwise "switched off, or blocked by a firewall" (DC5).
   - **Check these again** retries only the no-answer ports, because fastRefuse can turn one lost SYN into no answer.
4. The last result stays with the device:
   - in the drawer, after a reload too
   - in **Copy for IT** and share kind `device`
   - in MCP `get_device`

**Backend (new `internal/portscan`):**
- `presets.go`: fixed lists. A test pins each list, and Common has at most 100 ports.
- `Run(ctx, ip string, ports []int, o Opts) model.PortScanResult`, with `Opts{Pacer *portprobe.Pacer; Timeout time.Duration; Web func(ctx, ip string, port int, scheme string) model.WebService; Emit func(model.PortState)}`.
- `Describe(port, state)` gives the service name and plain line. It uses the remote-access names for 22, 3389 and 5900 (`remote.Kind`).
- `Service.StartPortScan(ctx, ip, preset, scanID, origin)`.

**Safety rules (each one has a test):**
1. **Connect only.**
   - Where `portprobe.SchemeFor(port)` (`internal/portprobe/tcp.go:37-46`) is empty, the connection closes without writing or reading a byte.
   - Only 80, 443, 8080 and 8443 get the existing `ProbeWeb` (`internal/portprobe/web.go:31`).
   - There is no TLS or HTTP guessing on other ports, so raw print ports (9100-9102, Zebra 6101 and 2501) never receive data (DC1).
   - No banners, logins, UDP or exploit checks.
2. **Scope (DC3).**
   - The address must be inside the real prefix (`netinfo.Iface.CIDR`, `internal/netinfo/rank.go:10-18`) of the interface of the running scan. When nothing runs, use the newest saved scan (`ScanResult.Self.Interface`).
   - That interface must not match `virtualRe`.
   - The target must not be this computer (`Host.IsSelf`), the network address or the broadcast address.
   - Otherwise: 400 `{"code":"not_this_network","error":"netdiag checks ports only on devices on this local network."}`.
3. **Session token** on the POST. One job per address and two in total (F4 heavy). A check never starts, cancels or replaces a scan (F9).
4. **Gateway (DC2).**
   - Common services only, at half rate with 8 workers (F13).
   - While a gateway check runs and for 30 s after, `Scan.QuietGateway(until)` holds back gateway misses: the live presence loop does not count them, and the gateway health result does not count toward the v0.6 N=2 streak or the storm guard's gateway rule.
5. **Timings (DC5).**
   - Timeout per port = max(3 × the device's `RttMs`, 250 ms), capped at 800 ms. It is 800 ms when the RTT is unknown.
   - Estimates shown before the start:
     - Common: about 2 s, up to 6 s on a silent device
     - the small presets: 2 s or less
     - First 1,024: about 5 s, up to 30 s silent
     - the gateway with Common: about 5 s, up to 12 s
   - The estimate is recomputed after the first 200 ports.
6. **'All ports' is not offered.** The server refuses `preset:"all"` with 400 `{"code":"preset_unavailable"}` until signing.
7. **Not an MCP action.**
   - There is no tool, `StartPortScan(` is forbidden, and `internal/portscan` is banned from mcpserver imports.
   - Agents read `get_device.host.portScan`.
8. **Rate:** at most 6 port checks per minute per computer (429).

**Storage (DC6):**
- `model.PortScanResult{Preset, StartedAt, FinishedAt string; Cancelled bool; Ports []PortState{Port int; State "open"|"closed"|"no_answer"; Service, Says string; Web *WebService}; Closed, NoAnswer int}`.
- It goes into the new `Host.PortScan`, **never** into `Host.OpenPorts`. `OpenPorts` drives presence and `presencePort`, printer detection, device type, diff (its common-ports rule) and remote access.
- `Scan.AttachPortScan(ip, mac, res)` attaches the result only if the host still has the MAC it had when the job started.
- The result is always in the job snapshot and in the F8 record (`portScan`, keyed by MAC), so it survives a reload and shows when nothing is running.
- MCP sees it read-only because Host is serialised whole (`internal/mcpserver/compact.go:401-404`). docs/mcp.md says so.

**API:** `POST /api/checks/portscan {"ip":"192.168.1.50","preset":"common","scanId":"…"}` → 202 `{id}`.
- SSE events: `portscan_port {port,state,service,says}`, `job_progress {done,total,etaSec}` and `done {result}`.
- Cancel keeps the partial result with `cancelled:true`.

**Defender and platform:**
- Native sockets, no child process, one device per click.
- At most 300 connects per second (150 for the gateway). Common is the default preset.
- Run a Defender scan on the RC after 10 checks.
- macOS: a Terminal-launched netdiag is exempt from Local Network privacy. A Finder launch is a field check.

**Wording:** `README.md:382` ("Only the ten fixed ports above are probed. netdiag is not a port scanner or vulnerability tool.") becomes "Every scan checks the ten ports above. **Check open ports** checks one device's services when you click it. netdiag never sweeps the network for open ports and is not a vulnerability tool."

**Backend**
- **`internal/wol`** (stdlib plus x/sys):
  - `Packet(mac)`: 6 × 0xFF, then the MAC 16 times, 102 bytes. No SecureOn password.
  - `ParseMAC`: `arp.NormalizeMAC` (`internal/arp/parse.go:37-65`), which rejects group, all-zero and all-FF MACs, plus a check that rejects the 0x02 private bit.
  - `DirectedBroadcast(p netip.Prefix)`: an error for /31, /32 and IPv6.
  - `Route{IfaceName, Src, Prefix, Broadcast}` and `PickRoute(ifaces, deviceIP, scanIface)`.
  - `Sender` and `UDPSender{Port: 9, Burst: 3, Gap: 100ms}`.
- **Bound to the scan interface.**
  - The route is the interface of the scan the device came from (`ScanResult.Self.Interface`), provided that interface's real prefix contains the device IP. The real prefix is `netinfo.Iface.CIDR`, not the scan CIDR, which `SuggestTarget` (`netinfo.go:90`) may narrow.
  - History and F8 candidates use the ranked interface whose prefix contains the last IP.
  - Otherwise the reason is `other_network`.
  - The route is picked again at click time.
- **Destination:** only that prefix's directed broadcast, on UDP port 9. For example, 192.168.68.68/22 → 192.168.71.255:9.
  - Never 255.255.255.255: Windows sends it out the lowest-metric route and macOS along the default route.
  - Never a unicast, and never another subnet (RFC 2644).
- **No listener.**
  - `net.Dialer{LocalAddr: &net.UDPAddr{IP: src}}` plus `DialContext(ctx, "udp4", bcast:9)` gives a connected `udp4` socket with SO_BROADCAST. With `"udp"`, Go would create a dual-stack AF_INET6 socket without SO_BROADCAST on Windows.
  - The socket only writes. It never reads, and it closes after about 250 ms.
  - On macOS it is pinned with `IP_BOUND_IF` (`unix.IP_BOUND_IF`, x/sys v0.49.0).
  - Each click sends 3 datagrams of 102 bytes, 100 ms apart.
- **`service.WakeCandidates(scanID) ([]model.WakeCandidate, error)`.**
  - Sources, newest first:
    - the current scan
    - the last 5 saved scans of the same range (`Store.Previous(cidr, beforeID)`, `internal/store/history.go:222`)
    - F8 records
  - Rows are de-duplicated by MAC, at most 50.
  - MAC choice: the F8 identity MAC, then `Host.MAC`, then `MACHistory` newest first.
  - Dropped MACs:
    - private and group MACs
    - the gateway's and this computer's MAC
    - a MAC that owns several IPs (`mac_multi_ip`: an extender or sleep proxy), even if that MAC is ignored
  - Eligible types: computer, server, nas, unknown.
  - "Not answering" means offline in live mode, or seen only through ARP with no open port.
  - The result is `Host.Wake{Possible, ReasonCode, Reason, Last}`, computed on the server in `state.mutate` from a per-scan wake context, so app.js has no copy of the rule.
  - Sources are a list, so v0.8 can add watched records with `lastIP`.
- **`service.StartWake(ctx, WakeRequest{ScanID, IP, Key string}, origin) (jobID string, err error)`.**
  - The MAC always comes from the candidate list, never from the request body. A `key` must match an eligible candidate, so the API is never a generic packet sender.
  - F4 kind `wake` (light):
    - one job per MAC (409 "Already waking this computer.")
    - 10 s between sends to the same MAC
    - 10 sends per minute in total (429)
    - at most 3 wake jobs
- **Verify (`runWake`, tested with a fake clock).**
  1. **Check first** (about 2 s): one ping plus TCP connects. If the device answers and ARP shows the target MAC: `already_awake`, and nothing is sent.
  2. **Send.** On error: `send_failed` with a plain reason. WSAENETUNREACH, EHOSTUNREACH and EACCES are mapped per OS.
  3. **Watch** for up to 180 s (300 s for storage):
     - Ping every 3 s for the first minute, then every 5 s.
     - Every other round, TCP connects through F13 to up to 3 ports the device had open that are **not** remote-access ports (`model.IsRemotePort`, the same rule as `presencePort`). If none are known: 445 and 139 for computers, or 5000, 445 and 80 for storage. A refused connection counts as present.
     - Read ARP for the MAC under any IP in the prefix, to find `newIP`: every round on Windows, every 10 s on macOS (where each read runs `arp -an`).
     - A live-scan presence event for the IP counts, at no network cost.
  4. **Outcome.**
     - Success: `woke`, then `Scan.Reprobe(ip)` (F5) so the row turns online.
     - Only a Windows reachable-state change: `probably_woke`. This needs a small additive `arp.Entry.State` from the NL_NEIGHBOR_STATE already read in `internal/arp/table_windows.go:27, 68-97`.
     - Time-out: `no_answer`, or `cant_tell` when the baseline was already Reachable or no probe signal was possible.
     - Cancel: `cancelled`.
  5. **Persist.**
     - `lastWake` is saved in F8 (`SetLastWake`) and pushed into the running scan's host. Host pointers are replaced, not mutated (`copyHost`, `internal/scan/state.go:148-156`).
     - A `wake` entry goes into the service EventLog for get_events.
     - Never a Notice.
- **Cost per click:** 3 datagrams, then at most about 45 pings and 70 TCP connects to one device over 3 minutes.

**API** (JSON; the POST needs the session token)
- `GET /api/wake/candidates?scanId=…` (read-only) → `[{mac, ip, name, deviceType, lastSeen, source:"scan|history|devices", answering, eligible, reasonCode, reason, lastWake}]`.
- `POST /api/wake` with `{"scanId":"…","ip":"192.168.1.40"}` or `{"key":"3C:52:82:11:22:33"}`:

  - 409: `{"error":"Already waking this computer.","id":"…"}`
  - 429: `{"error":"Wait a few seconds before sending another wake-up.","retryAfterSec":8}`

- `GET /api/jobs/{id}` → `{kind:"wake", state, phase:"checking|sending|watching|done", elapsedSec, limitSec, result:{mac, ip, newIp, outcome, seconds, at, signal, sent, broadcast, interface, message}}`.

## 9. Risks and mitigations
| Risk | Mitigation |
|---|---|
| A port check looks like reconnaissance to Defender or an IDS | One device per click; connect-only; a small default preset; 300/s; scan-interface scope; no MCP; 'All ports' hidden; RC scan; false-positive submission (V7-D8) |
| Raw print ports print junk | No bytes to non-web ports; ZD621 test |
| A cheap router stalls or blocks this PC during a check | Gateway gets Common only at half rate; `QuietGateway`; rate limit |
| Port check results pollute presence, device type or remote access | Results only in `Host.PortScan`, never `OpenPorts` |
| Nothing wakes (setting off, Wi-Fi, shut down) | Honest outcomes, three steps, help details, `lastWake` |
| A wake packet leaves the wrong adapter | Directed broadcast of the scan interface's own prefix; bound source; `IP_BOUND_IF`; never 255.255.255.255 |
| A stale or proxy MAC is woken | MAC only from candidates; extender and proxy rule |
| A device name injects Markdown, HTML or @mentions | `EscapeMarkdown`, html/template, server-built text, preview hash |
| Shared text leaks addresses | Preview with a who-sees-it line; alerts channel only; F11 redaction |
| A Make it beep label wastes media | Confirmation, 1 per minute, V7-D4 |
| A release this size slips | Independent milestones; fallback split v0.7.0/v0.7.1 (see master notes) |
| devices.json write conflicts with Defender | Debounce plus one retry; single writer |

## 10. Decisions needed
1. **V7-D1 Wake from MCP.** UI-only, or a probe-class tool? **Recommendation:** UI-only. Waking has a physical effect, and device text could steer an agent.
2. **V7-D2 The Wake a computer list in v0.7.** **Recommendation:** yes. Without it, a sleeping PC that is missing from a fresh scan can't be woken. It is the first item to slip.
3. **V7-D3 Eligible types.** **Recommendation:** computer, server, NAS and unknown. No TVs for now.

6. **V7-D6 Copy for IT contents.** **Recommendation:** include MAC and serial, since it is for IT. The chat preview shows them before sending.
7. **V7-D7 Share channel.** The alerts channel only, or any channel the bot is in? **Recommendation:** the alerts channel only.
8. **V7-D8 The port check before signing.** **Recommendation:** ship the small presets and First 1,024 ports with the RC Defender gate. Keep 'All ports' and any MCP tool until signing. Hold the whole feature if Defender flags the RC.
9. **V7-D9 probe_host updates the live scan.** **Recommendation:** yes, with `updatedLiveScan`.
