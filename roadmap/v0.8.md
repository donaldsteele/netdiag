# netdiag v0.8 "Always watching": detailed plan

> **Status update, 2026-10-17 (after this plan was written).** v0.5.7 shipped (tag `v0.5.7`) with four changes: the Windows refused-connection fix (`d04d794`), the DNS check that asks this computer's DNS servers (`64c21b7`), the "local network" wording (`fc9bd90`), and **Remote access** (`b54cb26`).
> - **Remote access (decision R1, made by the product owner).** Scans probe 22, 3389 and 5900 by default (`model.DefaultPorts` has 10 ports, `model.PortSSH/PortRDP/PortVNC`, `model.IsRemotePort`). A device gets a "Web / remote" link and a drawer **Remote access** section.
> - **How sessions open.** On Windows, netdiag starts Remote Desktop Connection itself (`internal/remote`, ShellExecute of mstsc.exe; accepted by the product owner). On macOS it uses Windows App or Screen Sharing through `/usr/bin/open`. SSH is **Copy SSH command** only.
> - **Limits.** Targets are local addresses only, never this computer.
> - **Routes.** `GET /api/remote`, `POST /api/scans/{id}/remote`, `GET /api/scans/{id}/remote.rdp`.
> - **Live presence** never dials remote ports (`presencePort` returns 0 when only remote ports are open).
> - **Compare** filters ports and port-based types to the ports both scans probed.
> - **Reading this plan.** Wherever it calls remote access "uncommitted", "working tree" or "unassigned", read it as **shipped in v0.5.7; build on it**. v0.6 must bring its three routes under the session-token guard.
> - **v0.5.8.** The remaining "Honest checks" fixes from the master roadmap's v0.5.7 list (Web server link, 15% threshold, export redaction and saved-scan export, port cap, Ignore confirmation, HOW-TO-OPEN wording, cooldown prune, gateway TCP fallback, same-host redirects and trust-this-certificate, RunHealth interface, opts_windows comment, bubbles docs) ship as **v0.5.8** before v0.6 starts.

## 1. Goal
netdiag keeps an eye on the local network without anyone remembering to press Scan. Flip **Keep watching this network** once, and every later time netdiag opens on the same network it starts watching by itself after a short countdown. It never watches a different network without asking first. Tick **Watch this device** on the till, card terminal, label printer or server, and netdiag says by name when it goes missing and when it is back. It also re-posts "Still not fixed" to team chat until someone acknowledges the problem. **Pause alerts for 1 hour** and quiet hours stop beeps and chat pings while you work on something or the office is closed, and one "While you were away" message follows. **Get help** produces a printable, copyable report for whoever helps you, and History now tells you in sentences what changed since an earlier scan.

## 4. Design

### 4.1 Shared groundwork (settings, model, alert policy, icons)

**Settings** (`internal/model/types_store.go:10-21` Settings, `:36-42` SettingsAlerts):
- `SettingsAlerts.PausedUntil string` (RFC 3339 UTC, "" means not paused).
- `SettingsAlerts.Quiet SettingsQuiet{Enabled bool; From, To string /*"18:00"*/; Days []string /*"mon".."sun", day the quiet period starts*/; AllowUrgent bool}`. Defaults: off, 18:00-07:30, Mon-Fri, AllowUrgent true.
- `SettingsAlerts.RemindEveryMin int`. Allowed values 0 (never), 30, 60, 240; default 60 (Decision 7).
- `Settings.Monitor SettingsMonitor{Enabled bool; Interface, CIDR, GatewayIP, GatewayMAC string; IntervalSec int /*default 60, clamp 30-300*/; AnnounceInChat bool /*default false*/}`.

**Lenient repair on load.** Add these rules to v0.6's `RepairSettings`, which `LoadSettings` uses and which reports each repaired path in `repaired`. `NormalizeSettings` (`internal/store/settings.go:49-103`) stays strict for `PUT /api/settings`: it rejects a bad time string, an unknown day or a disallowed `remindEveryMin` with a 400 that names the field. Load-time repair rules:
- A bad time string turns quiet hours off.
- Unknown day names are dropped.
- `RemindEveryMin` snaps to the nearest allowed value.
- A `PausedUntil` in the past, or more than 7 days ahead, becomes "".
- The Monitor interval is clamped.
- None of these may fall back to full defaults; the old "invalid file returns defaults" path is `store/settings.go:126-129`.

**Server-owned fields:**
- `PUT /api/settings` (full-document, used by `toggleSound` at `web/app.js:180-186` and by the dialog Save) must not overwrite fields owned by the new routes: `monitor.enabled`, `monitor.cidr`, `monitor.interface`, `monitor.gatewayIP`, `monitor.gatewayMAC` and `alerts.pausedUntil`.
- `service.SaveSettings` (`internal/service/settings.go:37-56`) gains a `preserveServerOwned` step for PUT requests. It copies these fields from the stored document. This stops a stale browser copy from un-pausing or switching off watching.

**Model** (`internal/model/model.go`):
- `ScanRequest.Monitor bool` marks the Keep-watching scan (`ScanRequest`, `model.go:12-21`).
- `Host.Watched bool` and `Host.Importance string` ("normal" or "important") are filled in `state.mutate` from the F8 inventory reader, beside `Host.Label`.
- `ScanResult.Missing []MissingDevice` (`ScanResult`, `model.go:184`), with `MissingDevice{MAC, LastIP, Name, Room, DeviceType, Importance, LastSeen, Since string; Once bool; Confirmed bool}`.
- `EventMissing = "missing"` with data `{missing:[...]}`.
- `NoticeEvent.Quiet bool` (`model.go:245`): "pause or quiet hours silence this notice on this computer".
- `LiveStatus.Monitor bool` and `LiveStatus.Missing int` (`model.go:278-287`).
- `model.TriggerExpectedMissing = "expectedMissing"` in `internal/model/types_conflict.go:11-19`.

**Inventory** (F8 `devices.json`†): each record gains `watch:{on bool, importance "normal"|"important", once bool, since}` and `lastIP`, `lastSeen` (watched records only; written at the 5-minute checkpoint and at Quit). Migration: a missing `watch` means not watched. Bump the devices.json `schemaVersion` from 1 (v0.7) to 2. v0.9 moves it to 3.

**`internal/alertpolicy` (new, pure, no I/O):**
- `Evaluate(now time.Time, a model.SettingsAlerts, loc *time.Location) State` with `State{Paused, Quiet bool; Until time.Time; AllowUrgent bool}`.
- `(State) SilentHere(sev string) bool` and `(State) HoldChat(sev string) bool` (critical passes when AllowUrgent).
- `NextMorning(now, a, loc) time.Time`: the quiet-hours end if quiet hours are on, else 08:00 local the next day.
- Always compares wall-clock `now` (never `time.AfterFunc`), because Go timers do not advance during sleep.
- Handles windows that cross midnight and DST with `time.Date(..., loc)`.

**Icons** (`tools/icons/icons.txt`, sprite currently 24,027 bytes, budget 40,960 in `internal/server/static_test.go:331`):
- add `i-eye eye` (watched badge, Watch switch);
- `i-life-buoy life-buoy` (Get help);
- `i-pause pause` (Pause alerts);
- `i-file-text file-text` (Report).

Rebuild with `tools/icons/build-sprite.mjs` and add the new ids to the reference check in `TestIconSpriteBudgetAndRefs` (`static_test.go:335`).

### 4.2 #7 Watch this device

**User experience, click by click:**
1. Open a device, for example the Zebra at 192.168.68.76. The v0.7 drawer action row gains a switch, **Watch this device** (`role="switch"`, `aria-checked`, the same pattern as `#mcp-enabled` at `web/index.html:479`). The help line under it reads "netdiag tells you by name when this device stops answering, and again when it is back. This works while netdiag is watching this network."
2. Switching it on shows "How important? **Normal** / **Important**" (radio group). The help line under Important reads "Important devices send an urgent alert to team chat." The status line confirms "Watching Front desk label printer."
3. When the device has no MAC: the switch is disabled with "netdiag can't watch this device yet: it hasn't seen its hardware address."
4. When the device uses a private Wi-Fi address (v0.7 flag), the drawer warns "This device uses a private address that changes now and then, so netdiag may lose track of it."
5. When the device is offline and not watched: the button **Tell me when it's back** (a one-time watch) confirms "OK. netdiag will tell you when Front desk label printer is back."
6. In the table, watched rows get an eye badge and the word "watched" (`.badge`, beside the NEW/OFFLINE badges at `web/index.html:195-199`).
7. A new filter tab **Missing** sits after **Offline** (`tabs`, `web/app.js:90-92`). It lists watched devices that are offline: "Front desk till (Reception) · Missing since 14:05 (2 h 10 min)". A list underneath, "Not seen in this scan", covers watched devices that are absent from the scan entirely ("last seen Tue 14 Oct 09:12 at 192.168.1.40"). Each entry has buttons:
   - **Check again now** (v0.7 F5, on its last address);
   - **Wake this computer** (v0.7 WoL rules decide whether it shows);
   - **Stop watching**.
8. Empty Missing tab: "All watched devices are here." If nothing is watched: "You are not watching any devices yet. Open a device and switch on Watch this device."
9. Banners: "Warning: Watched device missing · Front desk till (Reception) stopped answering at 14:05." (critical for Important). The same banner changes in place (v0.6 #1) to "Fixed at 14:17: Front desk till is back (was missing 12 min)."
10. **Settings > Watching > Watched devices** lists name, room, Normal or Important, and a **Stop watching** button (takes effect at once; the fieldset says "Changes here take effect at once.").
11. The **Problems right now** card (v0.6) lists missing watched devices first.
12. A one-off (non-live) scan shows "Not seen in this scan" but sends no alert.

**Backend:**

`internal/notify/notify.go`:
- `emit` gating (`:75-77`): `notifyConfig` (`internal/scan/integrate.go:105-127`) always sets `TriggerExpectedMissing: true`. There is no global switch; unwatching is the off switch.
- In `Observe` (`:112`), the `prev.Online && !cur.Online` branch (`:127-135`): if `cur.Watched`, emit `expectedMissing` (severity "critical" for important, else "warn"; title "Watched device missing"; key `notify.Key("expectedMissing", h, "")` = `expectedMissing|<MAC>|` (the v0.6 format; a `MissingDevice` with no host in the scan builds the same key from its inventory MAC)) *instead of* `printerOffline`/`deviceOffline`. This means one alert, not two.
- Recovery: when a watched MAC is online and its key is in the F2 open-key set, emit the F2 OK notice "Back".
- New `ObserveMissing(list []model.MissingDevice) []model.Notice`. It emits `expectedMissing` only for entries with `Confirmed` true.
- `pendingNew`: today a host first seen by ICMP has no MAC, and `newDevice` fires on its first `Observe` (`:119-124`). In v0.8, `newDevice` for a host without a MAC is held until the first `Observe` that carries a MAC, or until `FlushNew()`. Watched MACs never get `newDevice`.

`internal/scan/state.go`:
- `mutate` (`:78-114`) fills `Watched`/`Importance`.
- New op `checkMissing(confirm bool)`. It computes `Missing` = watched inventory MACs whose `lastIP` is inside this scan's range (`r.inRange`) and that no host carries. It mirrors the list to the header through the `onChange` hook (`:36`, set at `orchestrator.go:498-502`) and publishes `EventMissing`.

`internal/scan/orchestrator.go`:
- After the initial analysis (`r.st.analyze()` at `:591`): `checkMissing(false)`.
- `internal/scan/live.go` `liveCycle` (`:142`): after the probe loop (`wg.Wait()` at `:322`), call `r.st.FlushNew()` and `checkMissing(true)`. A device that is still absent after the initial sweep *and* one live cycle is confirmed, so it needs two looks, matching `OfflineAfterMisses = 2` (`model.go:75`).

`internal/scan/bus.go` `Publish` (`:42-95`) and `Subscribe` (`:103`): add a `missing *model.Event` slot that keeps the latest value and is replayed to late subscribers.

**Presence nudge** in `checkPresence` (`live.go:343-420`, watched hosts only):
1. A watched host with no ICMP and no open port today falls to the passive ARP comparison at `:362`. It now also gets one `r.d.TCP.Reachable(ctx, ip, 9, PresenceTCPTimeout)`. That is `portChecker.Reachable`, `orchestrator.go:180-189`, which counts `portprobe.Refused` as present. The call is a connect only; nothing is sent. It goes through F13 pacing.
2. If the watched MAC appears in this cycle's ARP read (`arpMAC`) under a *different* IP, the device moved: treat it as present and let the conflict and MAC-history code report the move. No missing alert.
3. The connect also makes the OS re-resolve the address, so the next cycle's table read (Windows drops Unreachable/Incomplete rows at `internal/arp/table_windows.go:75`) reflects reality.

**API routes:**
- `PUT /api/inventory/{key}`† (v0.7) body gains `"watch":{"on":true,"importance":"important","once":false}`. Response: the record. **Session token required.** Returns 400 `{"error":"netdiag can't watch this device yet: it hasn't seen its hardware address."}` when the key has no MAC.
- The `GET /api/scans/{id}` snapshot gains `missing[]`; hosts gain `watched` and `importance`.
- SSE: new event `missing` (replayed); `live` gains `missing`.
- **Check again now** on a missing entry uses `POST /api/hosts/{ip}/probe`† with `lastIP`. F5 is extended to accept an in-range address that is a watched device's `lastIP`, even when it is not in the host map. If it answers, it becomes a host.

**UI** (`web/index.html`, `web/app.js`, `web/styles.css`):
- Drawer action row block `#drawer-watch`.
- Badge in the IP cell.
- Tab `missing`; `matches(h,'missing') = h.watched && isOffline(h)` (`app.js:486-496`).
- A `<section id="missing-list">` under the table, shown only when `filter === 'missing'` and `missing.length` is non-zero, as a plain list. No inner scroller and no new table, so `visible()` and the host rows stay untouched.
- The fieldset in the Settings dialog (`index.html:441`).
- The `missing` SSE handler next to the `conflict` handler in `listen()` (`app.js:364-417`).

**Persistence:** devices.json watch fields (§4.1). Watched `lastIP`/`lastSeen` are saved at the checkpoint (`CheckpointInterval` 5 min, `internal/scan/integrate.go:22`) and at Quit.

**MCP:**
- `list_devices` filters `watched` and `missing` (`deviceFilters`, `internal/mcpserver/compact.go:280`). `missing` returns offline watched hosts plus `ScanResult.Missing` entries as rows with `missing:true, online:false, ip:lastIP`.
- `DeviceRow` (`compact.go:244`) gains `watched`, `importance` and `missing`.
- The `problems` filter includes missing watched devices.
- Watch flags are UI-only. v0.7's inventory writer `SaveDevice(` is already forbidden. The watch flag goes through the same `PUT /api/inventory/{key}` and `SaveDevice(`, so no new forbidden name is needed unless a separate setter is added.

**bubbles:**
- Alert key `notify.Key("expectedMissing", h, "")` = `expectedMissing|<MAC>|`.
- Fields: Name, Room, Looked after by, Model, IP, MAC, Missing since.
- Severity: critical for Important (reaches "mentions only"; Decision 1), warning for Normal.
- Resolved by the F2 OK notice. A **Tell me when it's back** watch is cleared by the service after its OK notice.

**Defender/platform:**
- One connect per watched ARP-only device per cycle; no sweeps; no child process on Windows.

For a watched device known only through the address table, the drawer says "Checked through this computer's address table only, so 'missing' can be late: a few minutes on Windows, up to 20 minutes on a Mac."

### 4.3 #11 Keep watching this network

**User experience, click by click:**
1. The header form (`web/index.html:32-60`) gains, next to **Live mode** (`:47-48`), `<label class="check"><input type="checkbox" role="switch" id="keep-watching"> Keep watching this network</label>`. The Settings dialog has the same switch in a new **Watching** fieldset.
   - Help: "netdiag starts watching this network by itself each time you open it. It never watches a different network without asking."
   - Turning it on during a scan: "netdiag will watch 192.168.1.0/24 through router 192.168.1.1 (TP-Link) each time it opens." If no scan is running, watching starts at once.
2. The next launch on the same network shows a card above the tiles: "netdiag will start watching this network in 40 s." with **Start now** and **Not now**. With no click, watching starts at 45 s.
3. The Live pill (`liveText`, `app.js:520-529`) reads "Watching · checked 12 s ago · 2 offline" for the monitor scan. Scan stays hidden and **Restart watching** sits next to **Stop live**, as in v0.6 #3; on a monitor scan, Restart keeps `monitor:true` and the monitor interval.
4. On a different network (another router, or the same CIDR with another gateway MAC), the card reads "You're on a different network (router 10.0.0.1). Watch this one instead?" with **Watch this network** and **Not now**. Nothing is swept before a click.
5. If the laptop moves while watching, the F9 per-cycle fingerprint check stops cycles *and* alerts and shows the same question. With the F9 storm guard: "netdiag lost this computer's connection to the network at 10:42. Alerts are on hold until it is back."
6. **Stop live** during watching: "Watching stopped. netdiag will start watching again the next time it opens." with **Turn off Keep watching**.
7. **Settings > Watching** also offers "Check every: 30 seconds / 1 minute (recommended) / 2 minutes / 5 minutes". The status reads "Watching 192.168.1.0/24 through router 192.168.1.1 (TP-Link), using Ethernet."

**Backend:**
- New `service.AutoWatch(ctx)` in `internal/service/watching.go`, plus `Server.StartMonitor()`. `cmd/netdiag/ui_cmd.go` calls it after `srv.Listen` (`:43`) and before `Serve` (`:60`), because `server.New` builds the service internally (`internal/server/server.go:60-66`).
- It runs only in `netdiag ui`, never in `netdiag mcp` (stdio), and only in the instance that holds the F9 single-instance lock.
- Steps:
  1. Read the fingerprint: interfaces, `Env.Gateway`, and the gateway's MAC from the ARP table. If the gateway MAC is absent, send one TCP connect to the gateway on 80 (no bytes), then read again.
  2. Compare it with `Monitor` using F9's fingerprint comparison.
  3. On a match, set state `starting` with a wall-clock deadline of now+45 s, re-checked by a 1 s ticker that reads the wall clock.
  4. Then `Service.Start(ScanRequest{CIDR, Interface, Live:true, Monitor:true, LiveIntervalSec: Monitor.IntervalSec})`.
  5. On a mismatch, set state `otherNetwork` and do not sweep.
- `ReplaceLive` (F9) makes UI Scan and MCP `start_scan` return `alreadyWatching` instead of cancelling (`internal/scan/registry.go:48-60` today).
- Manual Live mode keeps `DefaultLiveIntervalSec = 15` (`model.go:25`). Only monitor scans default to 60 s (Decision 2).
- `SetMonitor(enabled bool)` captures the fingerprint from the running scan's `Self`/`Gateway` header (`orchestrator.go:482-488`), or from the default interface.

### 4.5 #19 "Still not fixed" reminders

**User experience:**
- **Settings > Team chat (bubbles)** gets "Remind the team while a problem is still there: Every 30 minutes / Every hour / Every 4 hours / Never". Help: "If someone presses Acknowledge in team chat, the reminders stay quiet."
- The **Problems right now** card shows "since 13:05 (2 h 10 min) · reminded 3 times".
- In chat, the same alert card updates. Its title becomes "Still not fixed: Printer offline" and its text "Still not fixed after 2 h 10 min: Front desk printer (Reception) is offline."

**Backend (F10 router tick, once a minute, wall clock):**
- For each ledger entry that is open, posted, not held, eligible, below the cap, and has `now - lastPostedAt >= interval`: re-post with the **same dedupe_key and the same severity**, `renotify_after_s = interval_s - 60`, and `occurred_at = since`. Then increment `reminders`.
- **Every** post of an eligible trigger carries `renotify_after_s = interval_s - 60` while reminders are on. That includes the first post, coalesced updates and outbox re-sends after a restart. This changes the v0.6 content mapping: `0` stays only for **Never** and for triggers that never get reminders.
- Reason: bubbles reads the *stored* interval when it decides a repost's transition (`bubbles/internal/alerts/service.go:285` before `:294-300`; `dedupe.go:121-128`). An alert first posted with 0 would swallow the first reminder.
- A new interval takes effect from the next re-post.
- A re-send after a restart pings only if the interval has already passed.
- Test: `TestFirstReminderNotifies` against a real bubbles v0.2.0. Post with a 70 s interval, wait 75 s, re-post: the transition is `renotify_due`.
- bubbles decides what happens (`transition`, `bubbles/internal/alerts/dedupe.go:109-119`):
  - An open, unacknowledged alert past its interval becomes `renotify_due` and notifies.
  - An acknowledged one becomes `updated_other` and stays silent.
  - A higher severity is `escalated`, which notifies even when acknowledged. So a reminder never raises the severity.
  - The `-60 s` margin avoids a repost landing a few seconds before `renotifyDue` (`dedupe.go:121-131`) and being silently skipped.
- Eligible triggers: offline or missing devices, printer faults, failing checks, conflicts with severity fail. Never `supplyLow`, `newDevice` or info notices.
- Cap: 8 reminders per problem. After that the card reads "reminders stopped after 8".
- No reminders while held (paused or quiet).
- After a resume or a sleep jump (F9), reminders wait for the first full live cycle and the F2 reconcile.
- Reminders are spaced at no more than 10 per minute. The bubbles alert ingest limit is 60 per minute with a burst of 20 per app (`bubbles/docs/integrations.md:117`).
- No local re-beep (Decision 11).

**API:** no new route. `RemindEveryMin` is saved through the Settings dialog. `GET /api/alerts/state` adds `remindEveryMin`.

**Persistence:** ledger entries gain `reminders int`, `lastRemindedAt`, `lastPostedAt`. A missing value means zero.

**MCP:** `list_problems`† adds `reminders{count, lastAt}` and `held`. Read-only.

**bubbles:** works with today's server (default `alert_renotify_s` 1800, range 10-86400, `bubbles/internal/settings/settings.go:93`). Optional bubbles change 8 (a server-side renotify timer) would later replace re-posting.

**Defender/platform:** none.

## 9. Risks and mitigations
| Risk | Impact | Mitigation |
|---|---|---|
| Defender flags an unattended sweep at start-up (unsigned exe, flagged once) | Users lose netdiag | Off by default; user click; 45 s delay with Not now; 60 s interval; never on another network; no start at sign-in; clean-VM gate before release; submit as false positive; Decision 3 |
| False "missing" for ARP-only devices (Stale rows, macOS 20-minute cache) | Noise or late alerts | TCP 9 refused check; moved-MAC check; two looks before alerting; honest drawer note about lag |
| A watched device on DHCP moves address | False missing, then back | Moved-MAC check in the same cycle; MAC-keyed alert |
| Private-address phones watched | Watch lost | Warning text; key by MAC; Decision 12 |
| Alert storm when the laptop sleeps or moves | Chat floods | F9 storm guard covers `expectedMissing`; fingerprint mismatch stops cycles and alerts; reminders wait after resume |
| Reminders nag people | Users mute the bot | Ack silences them (bubbles `updated_other`); never escalate severity; supplies excluded; cap 8; quiet hours stop them; Never option |
| A reminder lands just before bubbles' interval and is skipped | Missed reminder | `renotify_after_s = interval - 60` |
| Held alerts lost if netdiag crashes during quiet hours | Silent outage | Held items live in the ledger; F2 reconcile on restart; digest after |
| Stale full-document PUT un-pauses or switches off watching | Confusing state | Server-owned settings fields; dedicated routes |
| Report leaks addresses or the SNMP community | Privacy | F11 redaction; preview plus privacy note; no auto-send |
| Device text injects HTML or Markdown into the report or chat | Script on 127.0.0.1, phishing links | `html/template`; CSP `default-src 'none'`; URLs as text; Markdown escaping tests |
| Header too crowded at 360/390 px | Guard tests fail | Alerts menu replaces the bell; switch in the 2-column controls grid; responsive/align/axe specs |
| Wrong sentence wording, for example on ports | Misleading | Table-tested `Describe`; raw details always under Show details |
| Only 20 scans kept | Old baselines vanish | Footer note; `changes_since` says the oldest date |
| The in-flight remote-access change conflicts (DefaultPorts, `presencePort`, `commonPorts`) | Merge churn | Decision 10; the `Describe` port table includes 22/3389/5900 |
| bubbles rate limit (60 per minute) | 429s | Reminder spacing ≤ 10 per minute; F10 outbox backs off on `Retry-After` |

## 10. Decisions needed
1. **Important watched devices send critical alerts?** Critical gets past "mentions only".
   - Options: critical / warning.
   - Recommendation: Important = critical, Normal = warning.
2. **Unattended interval.**
   - Options: 15 s (today's Live mode) / 60 s / user choice.
   - Recommendation: 60 s default for Keep watching (30 s-5 min in Settings); manual Live mode stays 15 s.
3. **Ship Keep watching before Azure signing?**
   - Options: ship / hold until signed.
   - Recommendation: ship. It only runs when the user opens netdiag and is delayed and gentle. Make the clean-VM Defender run a release gate, and hold the feature if Defender flags it.
4. **Does "Pause alerts" also hold team chat alerts?**
   - Options: this computer only / both.
   - Recommendation: both pause and quiet hours hold non-urgent chat alerts, and urgent ones pass when "Still tell me about urgent problems" is on. The digest follows.
5. **Report device list.**
   - Options: every device / problems plus counts.
   - Recommendation: plain report = problem devices, watched devices and counts by type. "Include technical details" = the full list.
6. **"Save this scan as normal" (pinned baseline) in v0.8?**
   - Recommendation: no, keep it in the backlog. Retention works on file names only (`internal/store/history.go:131`), so it needs a pins index and a copy to a new id. That is out of scope here.
7. **Reminder default.**
   - Options: Never / Every hour.
   - Recommendation: Every hour, since acknowledgements silence it, with the cap of 8.
8. **Announce start/stop watching in chat.**
   - Recommendation: off by default. A crash cannot be announced until bubbles has app presence.
9. **Where "Get help" lives.**
   - Options: sidebar navitem / header button / Help view (v0.9).
   - Recommendation: a sidebar navitem opening a dialog (nav count +1). v0.9's Help home reuses it.
10. **Remote access: RESOLVED.** It shipped in v0.5.7 by product-owner decision (see the status note at the top).
    - Options: ship in v0.5.7 / v0.7 / its own release.
    - The `Describe` port names include 22, 3389 and 5900. The Defender review of the "open remote desktop" path happens in the v0.5.7 field checklist.
11. **Local re-beep on reminders.**
    - Recommendation: no. The card shows "reminded N times".
12. **Watching devices without a MAC, or with a private address.**
    - Recommendation: block without a MAC; allow private addresses with the warning.
13. **Should one-off scans alert on missing watched devices?**
    - Recommendation: no. Show "Not seen in this scan" only.

## 12. Exit criteria

On a network with a different gateway MAC, nothing is sent before **Watch this network** is clicked except at most one TCP connect to the gateway on port 80 to learn its MAC (§4.3 step 1).
