netdiag - how to open it
=========================

Pick the right download
-----------------------
  Windows PC (most laptops)        netdiag-windows-amd64.zip
  Windows on ARM                   netdiag-windows-arm64.zip
  Mac with Apple chip (M1/M2/M3+)  netdiag-darwin-arm64.zip
  Mac with Intel chip              netdiag-darwin-amd64.zip

Not sure which Mac? Apple menu > About This Mac. "Chip: Apple M..." means
arm64. "Processor: Intel ..." means amd64.


WINDOWS
-------
1. Right-click the zip > Extract All. Open the new folder.
2. Double-click netdiag.exe.
3. Windows SmartScreen may say "Windows protected your PC" because the
   program is not code-signed. Click "More info", then "Run anyway".
   You only need to do this once per download.
4. Your browser opens to the netdiag page. Leave the black window open
   while you use it. Click Quit in the page (or press Ctrl+C in the
   black window) to stop.

You do not need an administrator password to run netdiag or to scan.

The first time you scan, Windows Defender Firewall may show a "Windows
Security Alert" about netdiag. It appears because a scan waits for
answers from devices on the network, such as Bonjour (mDNS) names. The
netdiag page itself can only be reached from this computer.

  - No administrator password? Click Cancel. "Allow access" would ask
    for an administrator password, and you do not need it.
  - If you have an administrator password, you can click "Allow access"
    instead.

After Cancel, netdiag still works: it finds devices by ping and by this
computer's list of nearby devices, reads printers, opens device web
pages and runs the health checks. Only Bonjour (mDNS) names may be
missing, and a device that answers nothing but Bonjour may not appear.
Some work computers block these answers without showing the alert; then
netdiag works the same way as after Cancel.


MAC
---
The Mac build is also not signed, so macOS blocks it the first time.

1. Unzip the file (double-click it in Finder).
2. Open Terminal (Applications > Utilities > Terminal).
3. Type "cd " (with a space), drag the unzipped folder into the Terminal
   window, press Return.
4. Remove the download block and make it runnable:

       xattr -d com.apple.quarantine netdiag
       chmod +x netdiag

5. Start it:

       ./netdiag

   Your browser opens to the netdiag page. Click Quit in the page (or
   press Ctrl+C in Terminal) to stop.

If step 4 says "No such xattr", that is fine: the block was not set.
If macOS still refuses to run it, open System Settings > Privacy &
Security, scroll down to the message about "netdiag", and click
"Open Anyway". Then run ./netdiag again.

When netdiag first scans, macOS may ask "Do you want the application
"netdiag" to accept incoming network connections?". Click Allow. This
lets netdiag find printers and devices that announce themselves (Bonjour /
mDNS). If you click Deny, the scan still works, but those devices may not
appear. You can change this later in System Settings > Network > Firewall.

No administrator password is needed.


WHAT YOU WILL SEE
-----------------
- Pick the network (interface) and the address range to scan. The range
  is filled in for you. Large ranges (bigger than /22) are refused.
- Click Scan. Devices appear as they respond. Printers show their toner
  and paper levels when the printer allows it.
- Click the web links to open a device's own settings page.
- Export JSON or CSV to save or send the results.
- The Health panel shows whether the router, DHCP, DNS and the web
  server are working. Recheck runs the checks again.
- Conflicts are listed when two devices share an address. Routers and
  Wi-Fi extenders often do this on purpose; use "Ignore this MAC" if so.
- Scans are saved in the History tab, and two scans can be compared.
- Alerts (live mode) show as a banner and a beep. Use Mute to silence them.
- If you close the browser tab, double-click netdiag again: it opens the
  same page.

Everything stays on this computer. netdiag only listens on 127.0.0.1
(this computer). The web page makes no internet requests. The only
outside request is the optional internet check, which asks one test
address whether the internet is reachable. The address can be changed in
Settings.

Problems? See README.md, section "Troubleshooting".
